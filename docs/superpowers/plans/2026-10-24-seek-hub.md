# Seek Hub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A self-hosted, Docker-packaged Seek Hub (Pi 4 first) that every PC syncs with over a Tailscale Funnel
endpoint, PC = truth for its own drives, hub = truth for everyone else's, hub never initiates.

**Architecture:** `seek-sync` gets protocol v2 (roles, hub messages), a TLS dialer and a PC-side hub session. A new
OS-independent crate `seek-hub` (library + `seek-hub` binary) holds an encrypted byte-level store of index copies,
a reply-only hub session, a hardened listener with a pairing window, and an admin CLI over a local socket. The
Windows service gains a hub mode that replaces LAN sync. Docker: a `scratch` image behind a userspace Tailscale
sidecar running Funnel (TLS-terminated TCP 443 → 127.0.0.1:47321).

**Tech Stack:** Rust 2021 (MSRV 1.85), tokio, snow 0.9, spake2 0.4, chacha20poly1305 0.10 (`XChaCha20Poly1305`),
postcard, zstd; new: `rustls` 0.23 (`default-features = false, features = ["ring", "std", "logging"]`),
`tokio-rustls` 0.26 (same: no default features, `ring`), `webpki-roots` 0.26, dev: `rcgen` 0.13; cargo-zigbuild
for `aarch64`/`x86_64-unknown-linux-musl`; Docker + `tailscale/tailscale`.

**Spec:** `docs/superpowers/specs/2026-10-24-seek-hub-design.md` (read it first; § numbers below refer to it)

## Global Constraints

- **Never `git commit`** (or let subagents commit) unless the user says so. "Checkpoint" steps = leave work in the
  tree, update the ledger below.
- `seek-core`, `seek-sync`, `seek-hub` have **no Windows dependencies** and must build for
  `x86_64-unknown-linux-musl` and `aarch64-unknown-linux-musl`. Timestamps: unix epoch **milliseconds**.
- Every task ends with `cargo test --workspace` green and `cargo clippy --workspace --all-targets -- -D warnings`
  clean. After agents run, delete stray empty files in the repo root.
- Port **47321**. Hub pairing code: **8 digits**, valid **120 000 ms**, **3 failed attempts in total** per window.
- Pre-auth limits: handshake ≤ **5 s**, first Noise message ≤ **256 bytes**, ≤ **16** unauthenticated connections,
  ≤ **60** handshake attempts / minute (global). Idle session close: **3 min** without received bytes.
- Quotas (defaults): **2 GB** stored per PC, **64** devices per PC. Journal compaction at **25 %** of the full
  copy's size or **50 MB**. PC polling interval **60 s**; upload debounce after an index change **2 s**.
- TLS: **1.3 only**, `webpki-roots`, hostname checked, **no plain fallback** for a `tls://` address.
- Hub never opens a connection and never writes a frame that is not a reply to a received one (except the
  one-shot `Unlinked` reply to a tombstoned key, itself a reply to the handshake).
- Encrypted files: header `SEEKENC1` (8 bytes) | key id (8 bytes, first 8 of BLAKE2s(key)) | 24-byte nonce |
  XChaCha20-Poly1305 ciphertext. Written to `<file>.tmp` then renamed.
- Env config of the hub: `SEEK_HUB_NAME` (default `Seek Hub`), `SEEK_HUB_LISTEN` (`127.0.0.1:47321`),
  `SEEK_HUB_LAN` (`0`/`1`, adds `0.0.0.0:47321`), `SEEK_HUB_PUBLIC` (e.g. `tls://seek-hub.tail1234.ts.net`),
  `SEEK_HUB_DATA` (`/data`), `SEEK_HUB_KEYS` (`/keys`), `SEEK_HUB_PC_QUOTA_MB` (`2048`), `SEEK_HUB_PC_MAX_DEVICES`
  (`64`).

## Review Focus

1. **Moving from LAN links to the hub keeps existing copies**: B already holds A's drives from LAN sync; after both
   link to the hub, B's cursors are valid against the hub's journal (same owner numbering) → B gets deltas, not a
   full copy. Test in Task 11 (`hub_link_keeps_lan_copies_and_gets_deltas`).
2. **Interrupted uploads never become visible**: a full copy cut off mid-transfer or a hub killed mid-write leaves
   the previous copy served intact. Tests in Task 5 (`tmp_file_left_behind_is_ignored`) and Task 6
   (`partial_full_upload_keeps_old_copy`).
3. **Slow but alive transfers through Funnel are not cut**: the 3-min idle timeout counts received bytes, not
   messages, so a 70 MB full copy at Funnel speed survives. Test in Task 8 (`slow_frame_is_not_idle`).
4. **Re-linking after an unlink works**: a tombstoned PC that is linked again (new pairing, same or new
   `host_id`/key) is accepted and its tombstone cleared. Test in Task 6 (`relink_clears_tombstone`).
5. **Addresses as users paste them**: `https://seek-hub.x.ts.net/`, `seek-hub.x.ts.net`, `TLS://Host:443`,
   `192.168.1.5`, `192.168.1.5:47321` all parse to the right transport; a bare hostname ending in `.ts.net` means
   `tls://`. Test in Task 3 (`hub_addr_parsing`).

### Task 7: reply-only hub session

**Files:** Create `crates/seek-hub/src/session.rs` (+ `session/tests.rs`).

**Interfaces:**
- Consumes: `Store` (Task 6), `Msg` v2 (Task 1).
- Produces: `async fn serve_pc(store: Arc<Store>, pc: Uuid, rd: SecureReader<R>, wr: SecureWriter<W>, idle: Duration) -> Result<(), Error>`.
  Strictly request → reply: a loop that reads one frame and writes zero or more reply frames; **no timers that
  write**. Replies: `Hello` → `Hello{role: Hub}` (protocol ≠ 2 → close); `Devices` → `set_pc_devices` then
  `Have{store cursors of those devices}` or `Refused`; `Full`/`Delta` → `put_*` then `Ack` / `Have{none}` /
  `Refused`; `Pull{cursors}` → `Catalog` + `serve` results for each other device as `Full`/`Delta` + `PullDone`;
  `Ack` → nothing; `SyncNow` → nothing; `Unlinked` → `unlink_pc`, close; `Open` → `Refused{NotSupported}`;
  `Have` from a PC → nothing (PCs never hold hub-owned data). After every handled message `touch_pc`.
  Compaction: after a `put_delta`, if `compact_due` contains the device, run `compact` in `spawn_blocking`
  (one at a time, global `Semaphore(1)`).
- `async fn reply_unlinked(wr)` — sends one `Unlinked` and closes (for tombstoned keys).

- [ ] **Step 1: Tests** (a test harness wraps the PC side: records every frame the hub writes and the index of the

### Task 8: listener, pre-auth limits, pairing window

**Files:** Create `crates/seek-hub/src/net.rs`, `crates/seek-hub/src/pairing.rs`.

**Interfaces — Produces:**
- `struct Hub { store: Arc<Store>, cfg: HubConfig, pairing: Mutex<Option<PairWindow>>, counters: Counters, … }`;
  `Hub::start(cfg, store) -> Result<Arc<Hub>, Error>` binds every `cfg.listen` address;
  `Hub::local_addrs() -> Vec<SocketAddr>`; `Hub::shutdown()`.
- Connection: first byte from the dialer `b'P'` (pairing) or `b'N'` (session) as in LAN sync; anything else →
  close. Whole pre-auth phase under `timeout(5 s)`; a `Semaphore(16)` permit held until authenticated (none
  available → close immediately); a sliding one-minute window of 60 attempts (over → close immediately).
  Session: `noise::accept_limited(io, keys, 256, |k| store.pc_by_key(k).is_some() || store.is_tombstoned(k))`;
  tombstoned → `reply_unlinked`; else `serve_pc`. A new session for the same PC stops the old one.
  Idle: the reader side wraps the stream in a byte-counting adapter; the session ends when **no bytes** arrived
  for 3 min (`slow_frame_is_not_idle`).
- Pairing: `Hub::open_pairing(now_ms) -> PairingCode` (8 digits, replaces any open window), `Hub::pairing_open() -> bool`.
  `b'P'` with no open window → close without writing. With a window: write status byte `1`, run
  `pair_host(code, PairInfo{role: Hub, user_sid: "", members: [], port: 47321})`; wrong code → one attempt used
  (window closes at 0 or expiry); success → `store.add_pc(..)` from the guest's info, window closes.
- `struct Counters` (atomics): `refused_handshakes`, `pairing_failures`, `ownership_violations`, `quota_hits`;
  logging rate-limited to one line per kind per minute.
